# مستند تست‌کیس‌های agent-eval

این فایل توضیح می‌ده هر کدوم از ۹۰ تست‌کیس توی پوشه‌ی `cases/` دقیقاً برای چی نوشته شده و چه سناریویی رو بررسی می‌کنه. برای خود کدها سراغ فایل‌های `cases/*.py` برو؛ این‌جا فقط توضیح فارسیِ روون هر کیسه.

شش گروه داریم:

1. **تست تکی هر نود، قطعی** (`node_deterministic_cases.py`) — فقط نود `analyze_intent` (تحلیل نیت مشتری) رو با LLM واقعی صدا می‌زنه و خروجی رو با یک مقدار دقیق مقایسه می‌کنه.
2. **تست تکی هر نود، هیئت‌داوری** (`node_judge_cases.py`) — نودهایی که پاسخشون متن آزاده (suggest_products، ask_question، product_agent، smalltalk_reply، handle_purchase) رو صدا می‌زنه و چند مدل LLM به‌عنوان داور رأی می‌دن که پاسخ خوبه یا نه.
   داورها علاوه بر متن مکالمه، **همون محصولات/FAQ‌ای که به ایجنت داده شده** رو هم می‌بینن؛ معیارِ «چیزی از خودش نسازه» دقیقاً بر همین اساس سنجیده می‌شه. بدون این، هر قیمت یا توضیح درستی که ایجنت از کاتالوگ نقل می‌کرد به‌اشتباه «ساختگی» حساب می‌شد.
3. **تست کل گراف، قطعی** (`graph_deterministic_cases.py`) — یک پیام کامل رو از اول تا آخر گراف رد می‌کنه (retrieval شبیه‌سازی‌شده، بقیه واقعی) و فیلدهای ساختاری نهایی state رو چک می‌کنه.
4. **تست کل گراف، هیئت‌داوری** (`graph_judge_cases.py`) — همون کل گراف، ولی این‌بار متن پاسخ نهایی که مشتری می‌بینه رو داورها بررسی می‌کنن.
5. **تست دقتِ ریتریو محصولات، قطعی** (`retrieval_ranking_cases.py`) — نودهای رتبه‌بندی/برش (`fuse_results_explore`/`fuse_context_product`) رو مستقیم و بدون هیچ تماس LLM روی یک کاتالوگ ۴۰ محصولی صدا می‌زنه و چک می‌کنه دقیقاً همون زیرمجموعه‌ی درست برگرده.
6. **تست گارد در برابر سوءاستفاده** (`guardrail_cases.py`) — پیام‌های نامرتبط/تلاش برای دور زدن دستورالعمل‌ها رو از کل گراف رد می‌کنه و چک می‌کنه ایجنت گمراه نمی‌شه.
